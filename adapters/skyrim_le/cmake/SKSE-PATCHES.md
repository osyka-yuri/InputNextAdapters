# SKSE 1.7.3 build boundary

`SkseSdk.cmake` fetches the official SKSE 1.7.3 source archive and verifies its SHA-256 before extraction. An offline source override is accepted only when its complete `src` tree and `skse_readme.txt` match that verified archive. The source tree and archive are inputs; configure copies sources into a private build directory before applying the guarded patches below.

The prepared SDK manifest covers every file under `src` using sorted relative paths and content hashes, after validating required layout paths including `common/ITypes.h`. `.prepared_state` is outside the hashed tree. Invalid caches are rebuilt through staging recovery. `SkseSdkPatches.cmake` holds the guarded substitutions, and its SHA-256 participates in the preparation fingerprint.

The target compiles only `GameAPI.cpp`, `GameBSExtraData.cpp`, `GameData.cpp`, `GameEvents.cpp`, `GameForms.cpp`, `GameMenus.cpp`, `GameReferences.cpp`, `GameRTTI.cpp`, `GameSettings.cpp`, `GameTypes.cpp`, and `ScaleformAPI.cpp`. These provide the SKSE globals and definitions used by the classic plugin layer: player/form lookup, loaded-mod lookup, event dispatchers, menu helpers, setting accessors, extra-data lookup, Scaleform allocation helpers, and SDK type support. `Utilities.cpp`, plugin manager, Papyrus engine registration, hooks, and the remaining SKSE runtime are not compiled by this target. `PapyrusEvents.h` remains available as a header.

The SDK target is x86-only, uses C++23 with `/permissive-`, and passes `/Zc:preprocessor` only to the MSVC compiler. SDK include roots are system headers, and SDK sources use `/W3` without changing warning policy for consuming plugin code.

## Private source patches

Each patch is applied only after an exact source-match check against the pinned archive contents; repeated substitutions also verify the expected occurrence count. Any mismatch stops configuration.

| ID | File | Change | Reason |
| --- | --- | --- | --- |
| LE-SKSE-001 | `src/skse/GameTypes.h` | Replace the `FindString` body that calls undeclared `StringFinder_CI` with a deleted declaration. | The official source tree does not define `StringFinder_CI` and has no call sites for this helper. The package does not invent its missing matching behavior. |
| LE-SKSE-002/003 | `src/skse/GameTypes.h` | Change two `Item*` locals in `tList<T>` to `T*`. | `Item` is undeclared there; the pointer type is the class template parameter and matches the surrounding return type and node layout. |
| LE-SKSE-004/005 | `src/skse/NiTypes.h` | Remove redundant `NiTLargeArray::` qualification from the in-class `Append` and `Resize` definitions. | Standard C++ requires those member definitions to use unqualified names inside the class body. |
| LE-SKSE-006/007 | `src/skse/GameData.cpp` | Bind `LoadedModFinder` to a local before passing it to `tList` methods. | The methods take a non-const lvalue reference, so binding the temporary is rejected by strict modern MSVC. |
| LE-SKSE-008/009 | `src/skse/GameSettings.cpp` | Omit definitions of `g_mapLocalHeight` and `g_localMapMinFrustumWidth`. | The original global initializers dereference Skyrim addresses during DLL load. Map globals are outside this plugin's SDK use; any reference fails at link time instead of reading game memory during startup. |
| LE-SKSE-010 | `src/skse/GameEvents.h` | Give the generic `BSTEventSink<T>` an inline default destructor. | The generic declaration lacks a destructor definition, which a plugin sink needs when it inherits the SDK type. Its callback remains non-pure because the SDK embeds generic sinks as opaque fields in game-owned classes; making it pure makes required headers abstract and uncompilable. A normal derived event sink overrides the callback. |
| LE-SKSE-011 | `src/skse/GameRTTI.h` | Remove invalid leading `##` token paste from the `DYNAMIC_CAST` macro's type cast. | The macro parameters are already substituted in the cast type; the extra paste is invalid with `/Zc:preprocessor`. RTTI symbol token-pasting is retained. |
| LE-SKSE-012 | `src/skse/Utilities.h` | Include `<string>` before declaring `std::string` APIs. | The header uses `std::string` without including its declaration; official project PCH settings do not provide it to these source files. |
| LE-SKSE-013 | `src/skse/GameMenus.h` | Include `ScaleformMovie.h` before the menu declarations. | `ScaleformCallbacks.h` makes an inline call through `GFxMovieView`, so the member type must be complete for both SDK source and plugin consumers. |
| LE-SKSE-014 | `src/skse/PapyrusEvents.h` | Qualify inherited `SafeDataHolder` calls/data with `this->` and dependent iterator types with `typename`. | Strict two-phase template lookup requires dependent base members to be qualified and dependent nested types to be introduced with `typename`. This leaves object layout and operations unchanged. Exact occurrence counts are guarded at configure time. |
| LE-SKSE-015 | `src/skse/GameEvents.h` | Define the generic sink callback inline to return `kEvent_Continue`. | The classic header leaves the non-pure callback undefined, so plugin-owned concrete sinks still retain an unresolved base vtable entry at DLL link. The method signature and vtable slot stay unchanged; consumers should override it in plugin-owned sinks. Opaque embedded sink fields retain their existing size and class layout. |
| LE-SKSE-016 | `src/skse/GameBSExtraData.cpp` | Omit the unrelated `BaseExtraList::GetDisplayName` implementation from the private build copy. | That implementation pulls two `GameExtraData.cpp` functions and their broader inventory dependencies into this minimal target. `GetByType`, the native backend's needed extra-data primitive, remains compiled from the original function body. The public declaration remains available, but consumers calling `GetDisplayName` must supply the relevant wider SDK implementation. |
| LE-SKSE-017 | `src/skse/GameForms.cpp` | Omit the `TESForm::CopyFromEx` definition from the private build copy while keeping the surrounding `LookupFormByID` definition and remaining source unchanged. | Its armor-copy branch is explicitly marked untested and is the only SDK reference to `BaseFormComponent::CopyFromBase`; this minimal adapter does not use it. The public declaration remains available, and any future consumer that calls `CopyFromEx` will fail at link time until a separately reviewed wider implementation is added. |

These changes do not alter SDK structure layouts or add game addresses. `GameThreads.h` is exposed for `TaskDelegate`; its implementation is header-only and no thread/hook translation unit is built. No Papyrus engine or hooks are compiled. The source archive is never patched in place.
